## 초기 실험에서 확인한 반복 생성

초기에는 결막염·백내장·유루증·무증상의 4개 라벨로 학습 환경과 평가 방법을 마련했습니다. 같은 이미지에 단순 진단형과 상세 서술형 텍스트를 연결해 비교했고, 상세 텍스트를 늘리는 것만으로 분류 결과가 좋아지지는 않았습니다.

출력에서는 마지막 문장을 토큰 한도까지 반복하는 현상도 나타났습니다. 보고서 §5.1은 학습 전처리의 종료 토큰 누락을 원인으로 분석합니다. 다음 실험에서 필요한 토큰이 학습 과정에 자동 적용되도록 구성하고, 완결된 응답과 반복 문제의 해소를 확인했습니다(§5.2).

## 이미지 입력과 학습 데이터를 함께 바꾼 최종 실험

7개 라벨로 범위를 넓히자 안검내반증·안검염·유루증 사이의 혼동이 드러났습니다. 원본과 안구 크롭을 함께 입력하는 시도에서도 성능 저하가 관찰됐고, 보고서는 두 입력의 중복·문맥 손실 등 가능성을 논의합니다.

최종 실험에서는 눈 밑 털의 착색과 주변 피부를 함께 포함하는 단일 패딩 크롭으로 입력을 바꾸고, 진단 JSON·Markdown·설명형·챗봇형 데이터를 통합했습니다. 같은 평가 이미지의 중간·최종 Macro F1은 0.6935에서 0.7404로 바뀌었습니다.

입력과 학습 데이터가 동시에 달라졌으므로 각 조치의 효과를 분리한 통제 실험은 아닙니다. 비용 제약 때문에 여러 설정을 충분히 반복하거나 통계적으로 검증하지 못한 한계도 보고서 §7.2에 남아 있습니다.

## 검색 근거와 설명형 학습 데이터

이호철은 질환별 로컬 문서와 웹 검색 결과를 모아 길이·출처·중복·질문 키워드에 따라 컨텍스트를 선별하는 파이프라인을 구현했습니다. 설명형 데이터 생성과 전체 전처리, VLM 학습·검증, YOLO 학습·크롭도 담당했습니다(§8.1).

초기 웹·서버리스·챗봇 구조와 연동 기반을 팀에 공유했습니다. 이후 담당 팀원들이 웹·서버리스 구축, 증상 추출·챗봇 데이터 생성, 베이스라인 모델링, 챗봇 통합을 이어가며 서비스를 완성했습니다.

졸업프로젝트 이후 [설명형 데이터 레포](https://github.com/ho72/pet-i-explanation-data)에 실패 출력 분리·dry-run·컨텍스트 보존·회귀 테스트를 추가하여 실행과 유지보수를 개선했습니다.
